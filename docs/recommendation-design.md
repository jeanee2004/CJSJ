# 정책 추천 설계안 (2026-10-29, 1차 구현 완료)

설문 응답과 공공 API 데이터를 합쳐 **"내가 받을 수 있는 제도를, 먼저 할 순서대로"** 보여 주는 단계를 결과 화면에 더한다.
지금의 진단 카드(`evaluate` → `applySchedules`)는 그대로 두고, 그 위에 판정 범위 확장과 순위를 얹는다.

표기: **확인** = 2026-10-29 실제 호출로 본 것, **미확인** = 문서·추정만 있는 것.

---

## 1. 지금 상태와 빈 곳

| 단계 | 지금 | 빈 곳 |
|---|---|---|
| 자격 판정 | 직접 정리한 5개 제도만 `evaluate()`가 판정 | API로 받은 나머지 제도는 판정 없이 목록만 |
| 일정 | 온통청년 날짜로 접수 중·마감 표시 (`applySchedules`) | — |
| 공공임대 | 공고 이름으로 혼인·자녀·나이만 가늠 (`fitsNotice`) | 소득·자산 기준 없음 |
| 순위 | 없음. 카드 5개가 같은 무게로 나열 | "무엇부터"가 없음 |

## 2. 자격 조건으로 쓸 수 있는 API 데이터 (실측)

### 2-1. 정부24 `supportConditions` — **확인, 아직 미연동**

- `GET https://api.odcloud.kr/api/gov24/v3/supportConditions?cond[서비스ID::EQ]=<id>` 를 같은 `DATA_GO_KR_KEY` 로 호출하면 200이 온다.
- 서비스마다 한 줄이 오고, `JA0110`/`JA0111`은 나이 하한과 상한이다. 나머지 `JAxxxx`는 해당하면 `"Y"`이다.

세종 주거 7건을 실측한 결과는 아래와 같다.

| 서비스 | 나이 | 특이 |
|---|---|---|
| 세종 전세보증금반환보증 보증료 지원 | 19~120 | JA0412 Y |
| 세종시 청년 주택임차보증금 이자지원 | null | JA0412 Y |
| 청년월세 지원사업 변경·중지신청 | 19~34 | 행정 절차라 이미 제외 중 |
| 세종형 쉐어하우스 청년임대주택 보급 | 18~120 | 가구 유형 코드 다수 Y |
| 보호종료아동 자립정착금 / 자활성공지원금 | 18~ | 주거 혜택 필터로 이미 제외 |

- **미확인**: 코드 각각의 뜻은 공식 명세를 아직 대조하지 못했다. 아래는 통상 알려진 뜻이다.
  - `JA0201~0205`: 중위소득 구간
  - `JA0322`: 직업 해당없음
  - `JA0404`: 1인 가구
  - `JA0411`: 다자녀
  - `JA0412`: 무주택
  - 구현 전에 data.go.kr 명세의 코드표로 대조해야 하고, 대조 전에는 나이만 쓴다.
- 소득 코드는 거의 모든 서비스가 전 구간 Y이다. 그래서 구간이 넓어 판정에 쓸 힘이 약하다.

### 2-2. 온통청년 — **확인 (이미 받는 응답 안에 있음)**

| 필드 | 실측 값 | 쓸 수 있나 |
|---|---|---|
| `sprtTrgtMinAge` / `sprtTrgtMaxAge` + `sprtTrgtAgeLmtYn` | 대부분 19/39, `LmtYn=N`이면 나이 제한 있음, `Y`면 없음 | **예** |
| `earnCndSeCd` | 세종 주거 6건 모두 `0043003`(기타), 금액 0 | 아니오: 소득은 `earnEtcCn` 글로만 있음 |
| `mrgSttsCd` | 모두 `0055003`(제한없음으로 추정) | 거의 의미 없음 |
| `earnEtcCn`, `plcySprtCn` | "중위소득 150% 이하", "임차보증금 3억원 이하" 등 | 화면에 그대로 보여 주는 용도 |

### 2-3. 출처끼리 어긋나는 값 — **확인**

| 제도 | 온통청년 필드 | 온통청년 본문 | 정부24 | 우리 `RULES` |
|---|---|---|---|---|
| 청년월세 지원 | 19~39 | 19~34 | 19~34 | 19~34 |

- 그래서 **API 나이를 직접 정리한 5개 제도의 판정에 덮어쓰지 않는다**. 값이 서로 다를 때는 카드에 "공고 원문 확인 필요"만 붙인다.

## 3. 구조

```
설문 응답(Answers, 브라우저에만)
   │
   ├─ evaluate()            : 직접 정리한 5개 제도 판정 (기존, 그대로)
   ├─ applySchedules()      : 온통청년 일정 반영 (기존)
   ├─ matchBenefit()   [신규]: API 제도를 Criteria 로 판정
   └─ rank()           [신규]: 위 둘을 한 줄로 세움 → "먼저 할 일" 3개 + 나머지
                                  ▲
/api/benefits  ── items[].criteria [신규] (서버에서 정규화, 하루 캐시)
```

- 설문 답은 지금처럼 서버로 보내지 않는다. 서버는 제도 쪽 조건만 정리하고, 사람과의 대조는 브라우저에서 한다.

### 3-1. 서버: `Benefit.criteria` 추가 (`api/_lib/benefits.ts`, `api/benefits.ts`)

```ts
interface Criteria {
  ageMin?: number; ageMax?: number          // 온통청년 필드 → 없으면 정부24 JA0110/0111
  noHome?: boolean                          // 정부24 JA0412 (코드표 대조 후에만 채움)
  text: string[]                            // earnEtcCn·지원대상·선정기준 원문 (판정 X, 표시용)
  from: ('youthcenter' | 'gov24')[]         // 어느 출처에서 왔는지
}
```

- 정부24 서비스 ID마다 `supportConditions`를 한 번씩 부른다. 지금은 7건이다.
  - 실패해도 목록은 그대로 내보내고 `criteria`만 비운다.
  - 기존 6시간 메모리 캐시와 하루 CDN 캐시를 그대로 탄다.
- `dedupe`로 합칠 때 `criteria`는 출처별 값을 모으고, 나이는 **온통청년 우선**으로 고른다. 일정 우선순위와 같은 규칙이다.

### 3-2. 브라우저: `matchBenefit(b, a)` (`src/lib/recommend.ts` 신규)

| 조건 | 결과 |
|---|---|
| 나이 범위 밖 | `no` (사유: "만 OO~OO세 대상") |
| `noHome` 이고 `a.ownsHome` | `no` |
| 위에 걸리지 않고 `text`가 있음 | `maybe`, "소득·재산 조건은 원문에서 확인" |
| 걸리는 것도 글도 없음 | `maybe` |

- 소득은 자동으로 제외하지 않는다. 중위소득 %로 비교하려면 가구원 수가 필요한데, 설문에 그 문항이 없기 때문이다. 설문 로직은 건드리지 않는다는 원칙이 있다.
- 한 사람의 응답에서 `ok`는 나오지 않는다. API 제도는 많아야 "확인해 보면 좋아요"까지다. 확실하게 "된다"고 말하는 것은 직접 검증한 5개 제도뿐이다.

### 3-3. 순위: `rank(verdicts, matches, today)`

한 줄 점수 대신 **정렬 키를 순서대로** 비교한다. 이렇게 해야 왜 이 순서인지 설명하기 쉽다.

1. **상태**: `ok` > `maybe`, `no`는 순위에서 뺀다.
2. **지금 할 수 있나**: 접수 중 > 30일 안에 시작 > 상시 > 모름 > 마감.
3. **계약 단계와 맞나**: `stage`가 `explore`나 `contract`면 대출·이자 지원과 보증료 지원을 앞에 둔다. 계약 전에 정해야 하기 때문이다. `paid`나 `movedin`이면 월세·임대료 지원을 앞에 둔다.
4. **혜택 크기**: 직접 정리한 5개 제도는 `compareCost`나 `RULES`로 연 환산 금액을 낸다. API 제도는 금액을 모르므로 같은 단계 안에서 뒤로 보낸다.
5. **동점이면** 직접 정리한 제도를 API 제도보다 앞에 둔다.

- 둘 중 하나만 받을 수 있는 제도(`EXCL_PICK_ONE`)는 순위에 **한 쪽만** 올린다. 이자지원과 버팀목 중에는 `compareCost`에서 6년 이자가 적은 쪽, 임대료 지원과 청년월세 중에는 총액이 큰 쪽이다.
- 마이홈 공공임대 공고는 순위에 넣지 않고 지금처럼 별도 섹션에 둔다. 공고 단위라 제도와 같은 기준으로 비교할 수 없다.

### 3-4. 화면 (`src/pages/Result.tsx`)

- **맨 위에 새 섹션 "먼저 할 일"**: 카드 3장까지 보여 준다.
  - 카드 내용: 제도명, 왜 추천했는지 한 줄(정렬 키 2~4에서 나온 문장), 기한, 신청 링크.
  - 3장이 안 되면 있는 만큼만 보여 준다.
  - API를 불러오지 못하면 직접 정리한 5개 제도만으로 순위를 매긴다(폴백).
- 아래의 기존 진단 카드 5개는 그대로 둔다.
- "추가로 확인해볼 혜택" 목록의 각 항목에 판정 배지(확인해 보면 좋아요)를 단다. `no`인 항목은 "조건이 맞지 않는 혜택 N건 보기"로 접는다.

## 4. 하지 않는 것

- 설문 문항 추가와 localStorage 구조 변경. 가구원 수, 재산 문항이 없어서 생기는 한계는 "원문에서 확인"으로 둔다.
- API 값으로 직접 정리한 5개 제도의 기준을 자동으로 바꾸는 것. 어긋나면 표시만 한다.
- 서버로 설문 응답을 보내는 것, 추천 결과를 서버에 저장하는 것.
- LLM 같은 외부 모델로 원문 조건을 해석하는 것. 결과가 매번 달라질 수 있고 근거를 보여 주기 어렵다.

## 5. 작업 순서 (커밋 단위)

1. `criteria` 서버 쪽: 온통청년 나이 필드를 매핑하고, 정부24 `supportConditions`는 나이만 연동한다. 단위 테스트와 `LIVE=1` 테스트를 함께 넣는다.
2. `matchBenefit` + 테스트: 나이 경계, 무주택, 원문만 있는 경우.
3. `rank` + 테스트: 단계별 순서, 둘 중 하나 제도 처리, 마감 제도는 뒤로, API 실패 폴백.
4. 결과 화면 "먼저 할 일" 섹션과 추가 혜택 배지.
5. `docs/api-integration.md`에 `supportConditions` 실측 결과를 추가한다.

## 6. 결정 사항 (2026-10-29)

1. **나이만 쓴다.** JA 코드(무주택 등)는 코드표를 대조하기 전까지 쓰지 않는다. 무주택은 제도 이름·요약·원문 조건에 "무주택"이 있고 설문에서 자가라고 답했을 때만 제외한다.
2. **청년월세는 34세로 판정**하고, 다른 출처(온통청년 필드 19~39)로는 결과가 달라지는 나이(35~39세)에만 "공고 원문 확인" 문장을 붙인다 (`flagAgeConflicts`).
3. **"먼저 할 일"은 3장을 먼저 보여 주고 나머지는 "더 보기"로 편다.** 개수는 `src/components/Recommend.tsx` 의 `TOP` 한 곳에서 바꾼다. 정해지지 않아 임시로 둔 값이다.
4. **금액 비교 기준은 사용자가 고른다**: 비교 기간(1·2·6년)과 버팀목 금리(범위 하단 / 소득으로 추정 / 범위 상단). 같은 선택을 "먼저 할 일" 정렬과 아래 이자 비교가 함께 쓴다. 새로고침하면 기본값(소득 추정·6년)으로 돌아간다. localStorage 구조는 건드리지 않았다.

## 7. 구현 메모

- 서버: `Benefit.ages`(출처별 나이), `Benefit.conditions`(원문 조건). 정부24는 서비스마다 `supportConditions`를 한 번씩 부른다. 2026-10-29 실호출에서 세 출처 모두 `ok`였다.
- 브라우저: `src/lib/recommend.ts` (`matchBenefit`, `flagAgeConflicts`, `amountOf`, `rank`), 화면은 `src/components/Recommend.tsx`.
- 금액(`amountOf`)은 비교 기간 동안 받는 돈(월세 지원) 또는 은행 금리로 빌릴 때보다 덜 내는 이자(대출)다. 세종 임대료 지원 10개월은 기간이 길어도 한 번만 센다 (매년 다시 받을 수 있는지는 **미확인**).
- 팀원 설문 교체(8aedc69)에 맞춰 공공임대 공고의 자녀 여부를 이전 Q8 대신 Q4 "자녀가 있는 가구"로 본다.
- 브라우저 캐시: `/api/benefits` 는 브라우저 1시간 캐시라 배포 직후에는 이전 응답(나이 정보 없음)이 보일 수 있다. 그 경우 나이로 거르지 않을 뿐 화면은 정상이다.

## 8. 남은 것

- 마감된 진단 제도(예: 세종 임대료 지원)가 접수 일정을 모르는 API 제도보다 뒤에 온다. 설계한 정렬 순서 그대로지만 어색하면 "진단 제도 먼저"를 2번째 키로 올릴 수 있다.
- 쉐어하우스가 온통청년·복지로 이름이 달라 두 번 나온다 (기존 문제).
- JA 코드표 대조, 가구원 수가 없어 소득 자동 판정 불가.
